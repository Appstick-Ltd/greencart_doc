# ⚡ Quick Start

Get **Hana Go** running on your device in under 5 minutes.

---

## 1️⃣ Extract the Project

After purchasing from CodeCanyon, extract the downloaded `.zip` file:

```
hana-go-v1.0.0.zip
└── hana_go/          ← Main Flutter project (this is your working folder)
└── hana_go_docs/     ← Documentation site (Docusaurus)
└── README.pdf        ← Quick reference PDF
```

---

## 2️⃣ Open in Your IDE

```bash
# Open in VS Code
code hana_go/

# Or open Android Studio → Open → select the hana_go/ folder
```

---

## 3️⃣ Install Flutter Packages

```bash
flutter pub get
```

You should see:
```
Resolving dependencies...
Got dependencies!
```

---

## 4️⃣ Configure Firebase (Optional for First Run)

For a quick first run without push notifications, you can skip Firebase. The app will launch with a warning in debug logs.

For full Firebase setup, see the [Firebase Setup](../firebase-setup) guide.

---

## 5️⃣ Run the App

```bash
# Make sure a device/emulator is running first
flutter devices

# Then run
flutter run
```

The app will build and launch. First build may take 60–90 seconds. Subsequent runs use hot reload and are near-instant.

---

## 🗺️ What You'll See

After launch, the app goes through this flow automatically:

```
Splash Screen (2s)
    ↓
Onboarding (2 slides — swipeable)
    ↓
Welcome Screen
    ↓
Login / Register
    ↓
Home Screen (main app)
```

:::tip First-Run Navigation
On first run, the app shows Onboarding. On subsequent runs, you'll go directly to the Home Screen (state is persisted via `get_storage`).

To reset to onboarding: clear app data on your device, or set `GetStorage().erase()` in `main.dart` during development.
:::

## 🔄 Development Workflow

### Making UI Changes
```bash
# 1. Run the app
flutter run

# 2. Edit any .dart file in lib/
# 3. Press 'r' in terminal → Hot Reload applies instantly
# 4. Press 'R' for Hot Restart if state reset is needed
```

### Switching Between Mock Data and Real API
All mock data lives in `lib/data/seeds/`. To connect real APIs:
1. Replace seed loaders in `lib/data/loaders/` with `dio` HTTP calls
2. Keep the same model structures in `lib/models/`
3. The UI will automatically reflect real data — no view changes needed

See [Mock Data → Real API](../customization/mock-data) for a detailed guide.

### Change App Name

**Android** — `android/app/src/main/AndroidManifest.xml`:
```xml
<application
    android:label="Your App Name"
    ...>
```

**iOS** — `ios/Runner/Info.plist`:
```xml
<key>CFBundleName</key>
<string>Your App Name</string>
```

### Change Bundle/Package ID

**Android** — `android/app/build.gradle`:
```groovy
android {
    defaultConfig {
        applicationId "com.yourcompany.yourapp"
        ...
    }
}
```

**iOS** — Open Xcode → Runner target → General → Bundle Identifier

## 🚀 Run the Documentation Site

The Docusaurus documentation site (what you're reading now) can also be run locally:

```bash
# Navigate to the docs folder
cd hana_go_docs/

# Install Node.js dependencies
npm install

# Start the dev server
npm start

# Opens at http://localhost:3000
```
